# iPlast | اصفهان پلاست

مینی‌اپ فروش B2B تلگرام، پنل مدیریت وب، API و ربات.

## ساختار

| مسیر | توضیح |
|---|---|
| `apps/miniapp` | پنل مشتری؛ مینی‌اپ داخل تلگرام (React + Vite) |
| `apps/admin` | پنل مدیریت وب (React + Vite) |
| `apps/api` | API (NestJS)؛ احراز هویت با initData تلگرام و JWT کوتاه‌مدت |
| `apps/bot` | ربات (grammY)؛ دکمه مینی‌اپ و دریافت متن، ویس، عکس و PDF و ارجاع به پشتیبان فروش |
| `packages/db` | مدل داده Prisma (PostgreSQL) |
| `packages/shared` | کد مشترک: بررسی امضای initData، قالب‌بندی ریال، تقسیم نقد و چک |
| `infra` | Dockerfileها و Caddy (HTTPS خودکار) |

## قواعد داده

- قیمتی که در لیست نیست یا «بزودی» است، `NULL` با وضعیت `INQUIRY` ذخیره و «استعلامی» نمایش داده می‌شود. هرگز صفر یا عدد ساختگی نیست.
- کد کالای حسابداری یکتا نیست؛ هر سایز یک `sku` داخلی دارد.
- نقش‌ها فقط از پایگاه داده خوانده می‌شوند، نه از کلاینت.
- توکن ربات و رمزها فقط در `.env` سرور هستند و هرگز در مخزن قرار نمی‌گیرند.

## اجرای محلی

```bash
pnpm install
cp .env.example .env   # مقادیر را پر کنید؛ DATABASE_URL را به localhost بدهید
pnpm db:migrate
pnpm --filter @iplast/shared build && pnpm --filter @iplast/shared test
pnpm dev:api    # http://localhost:3000/api/health
pnpm dev:miniapp
pnpm dev:admin
pnpm dev:bot
```

## انتشار روی سرور (اوبونتو، خارج از ایران)

یک بار روی سرور، با کاربر root:

```bash
curl -fsSL https://raw.githubusercontent.com/oftadeh/iplast/main/infra/setup.sh | sudo bash
```

این اسکریپت Docker را نصب می‌کند، کد را در `/opt/iplast` می‌گذارد، توکن ربات و آیدی عددی مدیر را می‌پرسد، `.env` را با رمزهای تصادفی می‌سازد و همه سرویس‌ها را بالا می‌آورد.

بعد رکوردهای A زیر را در DNS به IP سرور بدهید:
- `app.isfahanplast.co` برای مینی‌اپ
- `admin.isfahanplast.co` برای پنل مدیریت

**به‌روزرسانی خودکار:** سرور هر ۲ دقیقه گیت‌هاب را بررسی می‌کند. با هر commit جدید روی `main` دوباره بیلد می‌شود و نتیجه، موفق یا خطا، با ربات برای مدیر ارسال می‌شود. برای این کار به دسترسی ورودی SSH نیازی نیست.

## سرور داخل ایران (پراکسی)
اگر سرور به تلگرام، OpenAI و گیت‌هاب دسترسی مستقیم ندارد، iPlast از یک پراکسی V2Ray روی خود سرور استفاده می‌کند (`infra/proxy`):
xray در `/opt/iplast-proxy` روی پورت 10809 اجرا می‌شود. نصب با `OUTBOUND_PROXY=http://172.17.0.1:10809` و، اگر وب‌سرور دیگری پورت‌های ۸۰/۴۴۳ را دارد، `SHARED_WEB=172.17.0.1:8088`.
مدیر ارشد در پنل، بخش «پراکسی سرور»، لینک اشتراک جدید را می‌گذارد؛ هر کانفیگ قبل از فعال شدن با تلگرام آزمایش می‌شود و هر ۵ دقیقه اگر سرور فعال قطع باشد، سرور دیگری از همان اشتراک جایگزین می‌شود.

## انتقال مدیر ارشد
آیدی داخل `.env` (ADMIN_TELEGRAM_IDS) فقط اولین مدیر ارشد را می‌سازد. برای انتقال: در پنل، بخش «کارکنان»، آیدی تلگرام نفر جدید را با نقش «مدیر ارشد» اضافه کنید؛ سپس مدیر جدید حساب قبلی را غیرفعال می‌کند. اگر هیچ مدیر ارشد فعالی نماند، با راه‌اندازی دوباره آیدی داخل `.env` دوباره مدیر می‌شود.

## بدون دامنه (فعلاً)
مینی‌اپ، پنل ادمین و API روی یک آدرس HTTPS بالا می‌آیند. اگر هنگام اجرای `setup.sh` دامنه را خالی بگذارید، آدرس `<آی‌پی-سرور>.sslip.io` ساخته می‌شود. این یک نام رایگان است که به آی‌پی سرور اشاره می‌کند و تلگرام برای مینی‌اپ به همین HTTPS نیاز دارد. سایت عمومی یا دامنه‌ای راه نمی‌افتد.
- **پنل ادمین داخل مینی‌اپ است** (`/admin/`). مدیران و کارشناسان فروش آن را با حساب تلگرام خودشان باز می‌کنند، از کارت «پنل مدیریت» در صفحه‌ی اول یا با دستور `/admin` در ربات. دسترسی از روی آیدی تلگرام در دیتابیس بررسی می‌شود و بقیه پیام «دسترسی ندارید» می‌بینند.
- **سفارش در ربات:** مشتری سفارش را متنی یا صوتی می‌فرستد و با «✅ ثبت همین سفارش» ثبت می‌کند. کارشناس با دکمه‌های «تأیید / در بررسی / رد» وضعیت را تعیین می‌کند.
- **انتقال به دامنه‌ی واقعی:** وقتی دامنه آماده شد، `sudo bash /opt/iplast/infra/enable-web.sh isfahanplast.co` را اجرا کنید.

## به‌روزرسانی قیمت با هوش مصنوعی
در پنل مدیریت ← «به‌روزرسانی قیمت» PDF را بارگذاری کنید. ردیف‌ها با کد کالا وصل می‌شوند. ردیف‌های بدون کد یا با کد تکراری را هوش مصنوعی از روی نام، سایز و تعداد در بسته وصل می‌کند. PDF اسکن‌شده را هم خود مدل می‌خواند. همه‌چیز پیش‌نویس می‌ماند تا مدیر «انتشار» بزند. مدل با `OPENAI_PRICE_MODEL` تعیین می‌شود (پیش‌فرض: همان `OPENAI_MODEL`).

## حساب مشتری (فاکتور و دریافتی)
- **پنل مدیریت ← «حساب مشتریان»:** سفارش‌های تأییدشده‌ی بدون فاکتور، صدور فاکتور (قیمت اقلام استعلامی، تخفیف، حمل)، ثبت دریافتی (نقد، واریز، چک با سررسید شمسی)، وصول یا برگشت چک، گردش و مانده‌ی هر مشتری.
- **مینی‌اپ ← «حساب من»:** مدیر حساب شرکت فاکتورها، گردش حساب، پرداخت‌ها و چک‌ها و مانده را می‌بیند. کارشناس خرید (BUYER) به حساب دسترسی ندارد.
- صدور فاکتور و ثبت دریافتی از طریق ربات به مشتری اطلاع داده می‌شود.
- **رسید از طرف مشتری:** مشتری در «حساب من» عکس چک یا فیش واریزی را می‌فرستد (هر عضو شرکت، حتی کارشناس خرید). عکس با دکمه‌ی تأیید/رد در ربات برای کارشناس فروش آن مشتری و مدیرها می‌رود و در پنل مدیریت ← «تأییدها ← رسید پرداخت» هم هست. بعد از تأیید، واریزی از مانده کم می‌شود و چک «در جریان» می‌ماند تا وصول.
- **شرایط پرداخت:** در «حساب مشتریان» ← هر مشتری، مدیر درصد نقد/چک، سررسید چک‌ها و کارشناس فروش مشتری را تعیین می‌کند.

## تأیید دومرحله‌ای پیش‌فاکتور
1. مشتری سفارش را ثبت می‌کند ← «پیش‌فاکتور ثبت شد». پیام با دکمه‌ها برای کارشناس فروشِ همان مشتری می‌رود (اگر تعیین نشده، برای همه‌ی کارشناسان). مشتری در صفحه‌ی سفارش کارشناسش را می‌بیند و با دکمه‌ی «گفتگو» از طریق ربات با او حرف می‌زند.
2. کارشناس «تأیید کارشناس»، «اصلاح» (با توضیح) یا «رد» می‌زند (در ربات یا پنل مدیریت).
3. بعد از تأیید کارشناس، برای مدیرها پیام تلگرام و **پیامک** می‌رود و مدیر «تأیید نهایی» می‌زند.

پیامک با [کاوه‌نگار](https://kavenegar.com) فرستاده می‌شود: `KAVENEGAR_API_KEY`، شماره‌های مدیر در `ADMIN_SMS_NUMBERS` (با ویرگول) و در صورت نیاز `KAVENEGAR_SENDER`. اگر خالی باشد فقط پیام تلگرام می‌رود.

## دستیار سفارش (OpenAI)

مشتری در ربات یا در صفحه‌ی «سفارش سریع» مینی‌اپ سفارشش را می‌نویسد یا ویس می‌فرستد. دستیار با OpenAI Agents SDK فقط از کاتالوگ و لیست قیمت فعال اقلام را پیدا می‌کند و پیش‌نویس سبد می‌سازد. مشتری با دکمه‌ی «بررسی و ثبت در سبد» آن را در مینی‌اپ باز می‌کند. کارشناس فروش همه‌ی پیام‌ها و پیش‌نویس‌ها را می‌بیند.

تنظیمات در `.env`: `OPENAI_API_KEY` (خالی = خاموش)، `OPENAI_MODEL` (پیش‌فرض `gpt-6-luna`)، `OPENAI_TRANSCRIBE_MODEL` (پیش‌فرض `gpt-transcribe`).
