## ۲. محصول و نقش‌ها

مشتری‌ها (فروشگاه‌ها، نماینده‌ها، پیمانکارها) از داخل تلگرام کاتالوگ را می‌بینند، با قیمت مخصوص خودشان سفارش می‌دهند یا سفارش را متنی/صوتی به ربات می‌گویند. سفارش از چند مرحله‌ی تأیید رد می‌شود، به انبار می‌رود، ارسال می‌شود و فاکتور و حساب مشتری خودکار به‌روز می‌شود.

**نقش کارکنان** (`User.staffRole`، enum `StaffRole`):

| نقش | فارسی | کار |
|---|---|---|
| `ADMIN` | مدیر ارشد / مدیر | همه‌چیز؛ تأیید نهایی سفارش، کارکنان، تنظیمات، پراکسی |
| `SALES` | کارشناس فروش | مشتری‌های خودش، بررسی و قیمت‌گذاری پیش‌فاکتور، گفتگو |
| `WAREHOUSE` | انبار | آماده‌سازی و ثبت ارسال (بارنامه، راننده، پلاک) |

«مدیر ارشد» (owner) یک ADMIN ویژه است که نقشش را کسی نمی‌تواند عوض کند؛ آیدی‌اش در Setting `owner.telegramIds` است و اگر نباشد از `ADMIN_TELEGRAM_IDS` در `.env` خوانده می‌شود (`apps/api/src/common/owner.ts`).

**نقش اعضای شرکت مشتری** (`CustomerMember.role`، enum `MemberRole`): `OWNER` مدیر حساب (همه‌ی سفارش‌ها و حساب مالی)، `BUYER` کارشناس خرید (سفارش می‌دهد، حساب مالی نمی‌بیند)، `VIEWER` فقط مشاهده. یک مشتری چند کاربر تلگرام دارد.

## ۳. معماری

```
   کاربر تلگرام
       │
       ├── ربات @iplast_sellerbot  (apps/bot, grammY)
       │        │  POST /api/internal/*  با هدر x-internal-key
       │        ▼
       └── مینی‌اپ / پنل  ──HTTPS──►  iplast-front (Caddy روی 80/443 سرور)
                                         │  iplast.keyfitapp.ir → 172.17.0.1:8088
                                         ▼
                                   web (Caddy داخل compose)
                                   ├── /          → apps/miniapp (فایل استاتیک)
                                   ├── /admin/    → apps/admin   (فایل استاتیک)
                                   └── /api/*     → api:3000 (NestJS)
                                                   ├── postgres:16 (Prisma)
                                                   ├── redis:7
                                                   ├── /data/uploads (volume)
                                                   └── OpenAI / Telegram / کاوه‌نگار ── از راه proxy:10809 (xray)
```

- **ورود:** مینی‌اپ و پنل `initData` تلگرام را به `POST /api/auth/telegram` می‌فرستند. API امضای آن را با `BOT_TOKEN` بررسی می‌کند (`packages/shared/src/telegram-init-data.ts`) و یک JWT هشت‌ساعته می‌دهد. نقش کارکنان در **هر درخواست** دوباره از دیتابیس خوانده می‌شود (`SessionGuard` در `apps/api/src/common/session.ts`)، پس حذف یک کارمند فوراً اثر دارد.
- **ربات ↔ API:** ربات خودش منطق کسب‌وکار ندارد؛ برای ثبت سفارش، تأیید، رسید و پیام ایجنت به مسیرهای `/api/internal/*` درخواست می‌دهد با هدر `x-internal-key: $INTERNAL_KEY`. Caddy این مسیرها را از بیرون 404 می‌کند. API هم برای فرستادن پیام تلگرام مستقیم از `TelegramService` (`apps/api/src/common/telegram.service.ts`) استفاده می‌کند.
- **کارهای زمان‌بندی‌شده:** با `setInterval` داخل سرویس‌ها (مثلاً `OrdersService` هر ۱۰ دقیقه: انقضای پیش‌فاکتور، یادآوری چک؛ `WeeklyReport` در `growth.ts`؛ ربات هر ۲ دقیقه دکمه‌ی منو را همگام می‌کند). Redis فعلاً تقریباً استفاده نمی‌شود.
- **هوش مصنوعی:** OpenAI Agents SDK (`@openai/agents`). ایجنت فروش در `apps/api/src/assistant/sales-agent.service.ts` با ابزارهای سمت سرور (جستجوی کاتالوگ، قیمت، ثبت/لغو/اصلاح سفارش، ارسال PDF لیست قیمت، سپردن به کارشناس). خواندن PDF قیمت با AI در `apps/api/src/prices/price-ai.service.ts`.

## ۵. مدل داده (`packages/db/prisma/schema.prisma`)

| گروه | مدل‌ها | نکته |
|---|---|---|
| کاتالوگ | `Category` (درخت تا ۳ سطح)، `Brand`، `ProductFamily` (خانواده‌ی کالا)، `OptionAxis` (محور مثل سایز)، `Variant` (هر سایز، `sku` داخلی یکتا)، `VariantOption`، `Synonym`، `Media` | `Variant.stock` دستی (۰ = ناموجود)؛ `ProductFamily.packOnly` = فقط کارتنی |
| قیمت | `PriceList` (دارای تاریخ و وضعیت پیش‌نویس/منتشر)، `Price`، `PriceImportRow`، `PriceGroup`، `CustomerPrice` (قیمت اختصاصی) | قیمت ناموجود = `NULL` با `PriceStatus.INQUIRY` |
| تخفیف | `PaymentTerms` (درصد نقدی، درصد مدت‌دار، ماه چک)، `CustomerCategoryDiscount`، `SpecialDiscount` («تخفیف ویژه»: EXTRA/FIXED) | بهترین تخفیف ویژه برنده است، جمع نمی‌شوند |
| کاربر و مشتری | `User` (هر کاربر تلگرام، `staffRole` اختیاری)، `Customer` (`code` از ۱۰۰۱، `supportId` = کارشناس فروش)، `CustomerMember`، `JoinRequest`، `Invite` | |
| سفارش | `Order` (`number` خودافزا)، `OrderItem`، `OrderStatusEvent`، `Proforma` (مهلت ۴۸ ساعت)، `Shipment` | `PayMode`: `CASH` نقدی، `TERM` مدت‌دار |
| مالی | `Invoice`، `InvoiceItem`، `Payment` (نقد، واریز، چک با سررسید) | |
| گفتگو | `Conversation`، `Message`، `AssistantDraft` | |
| سیستم | `Setting` (کلید/مقدار JSON)، `AuditLog`، `Broadcast`، `Document` | |

**وضعیت‌های سفارش** (`OrderStatus`، متن فارسی در `STATUS_FA` در `orders.service.ts`):

```
SUBMITTED → SALES_REVIEW → (اگر قیمت/تعداد عوض شد) PROFORMA_SENT → مشتری تأیید → SALES_APPROVED
         → CONFIRMED (تأیید نهایی مدیر؛ فاکتور خودکار) → PREPARING → SHIPPED → DELIVERED
شاخه‌ها: NEEDS_FIX، PROFORMA_EXPIRED، REJECTED، CANCELLED
```

**کلیدهای Setting که در کد استفاده می‌شوند:** `owner.telegramIds`، `owner.transfer`، `sale.appBonusPct`، `proforma.ttlHours`، `bot.introVideo`، `seen.<userId>` (زمان آخرین بازدید هر صفحه‌ی پنل برای شمارنده‌ها). قبل از اضافه کردن کلید جدید، با `grep -rn "setting\." apps/api/src` الگو را ببینید.

**قواعد داده که نباید شکسته شوند:**
1. قیمتی که در لیست نیست یا «بزودی» است هرگز صفر یا عدد ساختگی نمی‌شود: `NULL` و نمایش «استعلامی».
2. «کد کالا»ی حسابداری یکتا نیست (۸۲ تکراری)؛ کلید هر سایز `sku` داخلی است.
3. مبالغ `BigInt` (ریال) هستند و در JSON رشته می‌روند. در کلاینت با `BigInt(...)` یا `fa()` کار کنید، نه `Number`.
4. نقش‌ها فقط از دیتابیس خوانده می‌شوند، نه از چیزی که کلاینت می‌فرستد.
5. هیچ داده‌ی ساختگی (قیمت، آمار، عکس، مشتری نمونه) در محیط واقعی نباشد. کاتالوگ seed واقعی است (لیست‌های آبان ۱۴۰۵).
6. درصد تخفیف یک مشتری را هرگز به مشتری دیگر یا در محتوای تبلیغاتی نشان ندهید.

## ۶. منطق اصلی کسب‌وکار

### قیمت هر مشتری (`apps/api/src/orders/pricing.ts` و `packages/shared/src/money.ts`)
1. قیمت لیست از `PriceList` منتشرشده‌ی فعال.
2. اگر `CustomerPrice` برای آن کالا هست، همان (بر همه مقدم).
3. وگرنه قیمت لیست منهای درصد مشتری برای نوع فروش (`cashPct` یا `termPct`)؛ اگر برای دسته‌ی کالا (یا دسته‌ی بالاتر) درصد جدا هست، آن.
4. «تخفیف ویژه»ی بهتر (برای همه یا همان مشتری، با شرط حداقل کارتن و بازه‌ی تاریخ) جایش می‌نشیند.
تابع اصلی `quote(prisma, variantIds, customerId, mode, terms)` است. هر جایی که قیمت نشان داده یا ذخیره می‌شود باید از همین بگذرد.

### روند تأیید
مشتری یا ایجنت سفارش می‌دهد → پیام با دکمه برای کارشناس فروش همان مشتری (یا همه‌ی کارشناس‌ها) → کارشناس قیمت استعلامی را می‌گذارد، تأیید/اصلاح/رد → اگر چیزی عوض شد پیش‌فاکتور برای تأیید مشتری → مدیر «تأیید نهایی» (پیام تلگرام و در صورت تنظیم، پیامک کاوه‌نگار) → فاکتور خودکار → انبار. همه‌ی گذارها در `OrdersService.decide()` با جدول «از کدام وضعیت به کدام» چک می‌شوند؛ وضعیت را جای دیگری مستقیم عوض نکنید.

### ایجنت فروش
همه‌ی پیام‌های مشتری (ربات و گفتگوی مینی‌اپ) اول به ایجنت می‌رسد. قاعده‌ی مهم در prompt: **هرگز ادعای کاری را نکند که ابزاری آن را تأیید نکرده** (یک بار گفته بود سفارش حذف شد در حالی که نشده بود). کارفرما ایجنت را «فوق هوشمند» می‌خواهد و سپردن به کارشناس فقط آخرین راه است. اگر کارمندی در ۳۰ دقیقه‌ی اخیر در آن گفتگو پیام داده باشد، ایجنت ساکت می‌ماند. `SALES_AGENT=0` ایجنت را خاموش می‌کند.

### اعلان‌ها
کارفرما پیام کم می‌خواهد: انتشار موفق بی‌صداست، فقط خطا خبر داده می‌شود؛ پشتیبان هفتگی بی‌صدا فرستاده می‌شود؛ هشدار کمبود دیسک حداکثر روزی یک بار. پیام جدید برای مدیر اضافه نکنید مگر لازم باشد.

## ۷. قواعد کدنویسی

**کلی**
- TypeScript با `strict`. قبل از هر commit: `pnpm typecheck`.
- سبک کد فشرده است: خط‌های بلند (تا حدود ۱۶۰ تا ۲۰۰ نویسه)، توابع کوتاه، بدون لایه‌ی اضافه (repository، DTO class، state manager). کد جدید را شبیه فایل‌های کناری بنویسید.
- **کامنت‌ها انگلیسی** و فقط برای «چرا»، نه «چه». متن‌هایی که کاربر می‌بیند (پیام خطا، برچسب، پیام ربات) **فارسی** هستند.
- پیام خطای API فارسی و قابل نمایش مستقیم به کاربر است: `throw new BadRequestException('…')`. کلاینت `message` را همان‌طور نشان می‌دهد.
- اعداد ورودی کاربر ممکن است فارسی باشند: `toEnDigits`، `rialOf`، `int` در `common/validate.ts`.
- وابستگی جدید فقط وقتی واقعاً لازم است؛ نسخه‌ها دقیق (بدون `^`) در `package.json`.

**API (NestJS)**
- یک ماژول؛ هر کنترلر جدید را در `app.module.ts` ثبت کنید.
- دسترسی: `@UseGuards(SessionGuard)` روی کلاس، و `@Staff('ADMIN', ...)` برای مسیرهای کارکنان. بدون نقش = هر کاربر واردشده. کاربر فعلی با `@Session() s: SessionClaims` (`s.sub` = id کاربر، `s.staff` = نقش).
- مسیرهای کارکنان با `admin/...`، مسیرهای مشتری با `me/...` یا `orders/...`، مسیرهای ربات با `internal/...` و بررسی `x-internal-key`.
- اعتبارسنجی دستی با توابع `validate.ts` (zod فقط برای ابزارهای ایجنت).
- تغییرهای مهم را با `audit(prisma, actorId, action, entity, id, before, after)` ثبت کنید.
- Prisma مستقیم در کنترلر مجاز است؛ منطق مشترک در سرویس (`OrdersService`، `AccountingService`، …).

**فرانت (مینی‌اپ و پنل)**
- React 18 بدون router و بدون کتابخانه‌ی UI/state. مینی‌اپ: stack مسیرها در `App.tsx` (`go`/`back`). پنل: hash به شکل `#<area>/<page>[/<id>]` و درخت منو `AREAS` در `apps/admin/src/App.tsx`.
- درخواست‌ها فقط با `api<T>(path, {method, body})` و در پنل `useApi<T>(path)` از `lib.ts`.
- CSS ساده در `styles.css` هر اپ با متغیرهای رنگ در `:root` و حالت تاریک. پنل مدیریت ابزار کار است (سایدبار تیره، یک رنگ آبی برای عمل)، **نه** شبیه مینی‌اپ. مینی‌اپ رنگ برند زرشکی لوگو (`#5E1430`/`#8A1C46`) و آبی روشن دارد.
- همه‌چیز راست‌به‌چپ، اعداد با `Intl.NumberFormat('fa-IR')`، تاریخ شمسی.
- صفحه‌ی جدید پنل: فایل در `apps/admin/src/pages/`، اضافه به `AREAS` با `roles`، و در صورت نیاز شمارنده در `Queue` و `admin-dashboard.controller.ts`.

**ربات**
- یک فایل `apps/bot/src/main.ts`. منطق کسب‌وکار در API؛ ربات فقط نمایش، دکمه و `internal(...)`.
- callback data کوتاه (محدودیت ۶۴ بایت تلگرام) با الگوی `<پیشوند>:<شناسه>:<عمل>`، مثل `os:<orderId>:sales_ok` (وضعیت سفارش)، `pf:` (پیش‌فاکتور)، `pay:` (رسید).

**Migration**
- مدل را در `schema.prisma` عوض کنید و `pnpm db:migrate` (یعنی `prisma migrate dev`) بزنید. نام پوشه به شکل `YYYYMMDDHHMMSS_name` است.
- migration روی داده‌ی واقعی اجرا می‌شود: ستون جدید یا پیش‌فرض داشته باشد یا nullable باشد.
- **هرگز migration پاک‌کننده‌ی داده بدون اجازه‌ی صریح کارفرما نسازید** (یک بار با اجازه‌اش داده‌ی آزمایشی پاک شد: `20261108235900_clear_test_data`).
- اگر migration روی سرور شکست بخورد، سایت با جدول‌های قبلی بالا می‌ماند و خطا در تلگرام برای مدیر ارشد می‌رود (`AuthService.reportFailedMigrations`). یک migration ناموفق (خطای P3009) همه‌ی بعدی‌ها را متوقف می‌کند؛ رفع آن با `prisma migrate resolve` روی سرور است و قبلش باید از کارفرما اجازه گرفت.

## ۸. اجرای محلی و آزمون

پیش‌نیاز: Node 22، pnpm 10 (`corepack enable`)، PostgreSQL 16 (یا `docker compose up -d postgres redis`).

مینی‌اپ و پنل بیرون از تلگرام `initData` ندارند. برای آزمون محلی با `signInitData` از `packages/shared` یک initData امضاشده بسازید (همان کاری که `e2e.mjs` می‌کند).

`e2e.mjs` کل روند (کاتالوگ، ورود، سفارش، تأییدها، پیش‌فاکتور، فاکتور، دریافتی، تخفیف ویژه، کارتنی) را می‌آزماید. با هر قابلیت جدید چند گام به آن اضافه کنید.

## ۹. روند کار تا امروز

1. کارفرما (HRO) درخواست را به فارسی می‌نویسد.
2. کار روی یک شاخه انجام می‌شود (قبلاً `next`، اخیراً `claude/...`)، typecheck و e2e اجرا و برای تغییر ظاهری اسکرین‌شات گرفته می‌شود.
3. Pull Request به `main` باز می‌شود با توضیح فارسی و ساده (چه چیزی برای کاربر عوض می‌شود).
4. کارفرما بررسی می‌کند. **ادغام در `main` یعنی انتشار روی سرور واقعی**، پس فقط وقتی کارفرما گفت «نصب کن» ادغام می‌شود. کارهای پایداری (deploy، پشتیبان، دیسک) را کارفرما اجازه داده بدون پرسیدن نصب شوند.
5. چند دقیقه بعد سایت را بررسی کنید (`/api/health`). اگر deploy شکست بخورد، پیام خطا با لاگ در تلگرام مدیر ارشد می‌آید.

PRهای تا امروز: #1 روند فروش و پیش‌فاکتور، #2 شرایط فروش نقدی/مدت‌دار، #3 متن‌های ربات و پیشخوان و جذب مشتری، #4 کد مشتری و درخواست عضویت، #5 شمارنده‌های منو و انتقال مدیر ارشد، #6 پاک کردن داده‌ی آزمایشی، #7 درخت دسته و تخفیف ویژه و فروش کارتنی، #8 تا #10 پایداری deploy، #11 پراکسی جلو و پشتیبان هفتگی.

**ترجیحات کارفرما:**
- پاسخ و متن‌ها فارسی، روان و رسمی؛ اصطلاح فنی می‌تواند انگلیسی بماند.
- پنل مدیریت ساده و مرتب (قبلاً «گنگ و به هم ریخته» توصیف شده بود)؛ هر بار ساده‌تر کنید، نه شلوغ‌تر.
- مهم‌ترین‌ها: روند سفارش و تأیید (مشتری → کارشناس → مدیر ارشد)، ارسال، چک و پول، درصد هر مشتری، اسناد مالی، ایجنت هوش مصنوعی. موجودی انبار اولویت ندارد (کارخانه تقریباً همه‌چیز را دارد).
- صفحه‌ی اول مشتری کارت «تکرار آخرین سفارش» نداشته باشد.
- پیام مدیریتی کم.

1. **نشانه را دقیق کنید:** کدام بخش (مینی‌اپ، پنل، ربات، API)، کدام کاربر و نقش، کدام سفارش (شماره‌ی `#`)، چه پیامی دیده شد.

| مورد | مقدار |
|---|---|
| سرور | mobinhost، داخل ایران، `87.107.129.163`، دیسک ۴۰ گیگ |
| کد | `/opt/iplast` (کپی git از `main`)، تنظیمات `/opt/iplast/.env` |

| دسترسی خروجی | سرور ایران مستقیم به تلگرام/OpenAI/گیت‌هاب/npm نمی‌رسد؛ xray در `/opt/iplast-proxy` (میزبان: `127.0.0.1:10809`، داخل Docker: `proxy:10809`). اشتراک VPN از پنل ← تنظیمات ← «پراکسی سرور» عوض می‌شود |

| پشتیبان | جمعه ۰۳:۳۰، `/opt/iplast-backups/` (۸ نسخه)، فایل کامل بی‌صدا با ربات برای مدیر ارشد؛ `settings.tar.gz` (شامل رمزها) فقط روی سرور |
| دسترسی به سرور | SSH ورودی از محیط ابری بسته بود؛ کارها یا با انتشار خودکار (pull) یا از راه کنسول VNC پنل mobinhost انجام شده است |

جزئیات نصب، پشتیبان و بازگردانی: پیوست انتهای همین سند.

**درس‌هایی که گران تمام شد:**
- **دیسک پر (۲۰۲۶-۱۱-۰۹):** دیسک ۴۰ گیگی ۱۰۰٪ پر شد، PostgreSQL با `ENOSPC` متوقف شد و چند deploy و یک migration شکست خورد. حالا autodeploy ایمیج‌ها و build cache قدیمی را پاک می‌کند (هرگز volume را)، لاگ کانتینرها محدود است (۳×۲۰ مگ) و زیر ۵ گیگ هشدار می‌دهد. اگر deploy با خطای عجیب شکست خورد، اول `df -h` را ببینید.
- **migration ناموفق** همه‌ی بعدی‌ها را قفل می‌کند (P3009). بعد از رفع علت: `prisma migrate resolve --rolled-back <name>` و بعد `migrate deploy`، با اجازه‌ی کارفرما.
- **ربات و پراکسی:** grammY به `HTTPS_PROXY` اعتنا نمی‌کند؛ `TunnelAgent` در `apps/bot/src/main.ts` لازم است. کانتینر proxy باید `/etc/ssl/certs` را mount کند.
- **کنسول VNC مرورگر** نویسه‌های shift‌دار را گاهی اشتباه تایپ می‌کند؛ دستورهای کوتاه یا اسکریپت.
- **سرور فقط از داخل ایران** در دسترس است؛ ابزارهای خارج از ایران ممکن است سایت را نبینند.

## ۱۵. نمونه: افزودن یک قابلیت از صفر تا سرور

فرض: «یادداشت داخلی روی مشتری که فقط کارکنان می‌بینند».

6. بعد از «نصب کن» کارفرما: ادغام، و چند دقیقه بعد بررسی سایت.

## ۱۶. شروع کار با یک دستیار هوش مصنوعی دیگر

این متن را همراه دسترسی به مخزن به دستیار بدهید:

> تو روی پروژه‌ی iPlast کار می‌کنی (مخزن `oftadeh/iplast`). اول `docs/DEVELOPMENT.md` (همه‌چیز در آن است) و بعد `packages/db/prisma/schema.prisma` را کامل بخوان. قواعد بخش ۵ و ۷ را رعایت کن: قیمت ساختگی نساز، مبالغ BigInt ریال، متن کاربر فارسی، کامنت انگلیسی، سبک کد مثل فایل‌های کناری. روی یک شاخه کار کن، `pnpm typecheck` و آزمون e2e را اجرا کن و PR به `main` باز کن. ادغام در `main` روی سرور واقعی منتشر می‌شود، پس بدون اجازه‌ی من ادغام نکن. هیچ رمزی را در کد یا commit نگذار. migration پاک‌کننده‌ی داده و هر کار روی سرور که برگشت‌پذیر نیست را اول از من بپرس. با من فارسی صحبت کن.

اگر دستیار به سرور دسترسی ندارد (معمولاً ندارد)، همان انتشار خودکار کافی است: کد را به `main` برسانید و سرور خودش به‌روز می‌شود. برای کار مستقیم روی سرور، دستورهای پیوست را در کنسول mobinhost اجرا کنید.

## پیوست: نصب، پشتیبان‌گیری، بازگردانی و عیب‌یابی سرور

(همان محتوای `docs/BUILD.md`؛ شماره‌ی بخش‌ها مال همان سند است.)

### ۲. پیش‌نیازها

- سرور اوبونتو ۲۲.۰۴ یا ۲۴.۰۴، حداقل ۲ گیگ رم و ۲۰ گیگ دیسک، دسترسی root (SSH یا کنسول VNC).
- یک ربات تلگرام از [@BotFather](https://t.me/BotFather) و توکن آن.
- آیدی عددی تلگرام مدیر ارشد (مثلاً از [@userinfobot](https://t.me/userinfobot)).
- اختیاری: کلید OpenAI برای دستیار سفارش و به‌روزرسانی قیمت از PDF؛ کلید کاوه‌نگار برای پیامک.
- یک نام دامنه با HTTPS. تلگرام مینی‌اپ را فقط روی HTTPS باز می‌کند.
- **سرور داخل ایران:** یک لینک اشتراک V2Ray (subscription) یا چند لینک `vless://`، `vmess://` یا `trojan://`، و یک دامنه روی Cloudflare.

### ۳. نصب روی سرور خارج از ایران

```bash
curl -fsSL https://raw.githubusercontent.com/oftadeh/iplast/main/infra/setup.sh | sudo bash
```

`setup.sh` این کارها را می‌کند:
1. Docker و git را نصب می‌کند و کد را در `/opt/iplast` می‌گذارد.
2. توکن ربات، آیدی مدیر، کلید OpenAI و دامنه را می‌پرسد و `.env` را با رمزهای تصادفی می‌سازد (`chmod 600`).
3. به‌روزرسانی خودکار (`iplast-autodeploy.timer`) و پشتیبان‌گیری هفتگی (`iplast-backup.timer`) را نصب می‌کند.
4. همه‌چیز را می‌سازد و بالا می‌آورد و کاتالوگ (۹۸ خانواده، ۸۸۳ سایز) را یک بار بارگذاری می‌کند (`.seeded`).

اگر دامنه را خالی بگذارید، آدرس `<آی‌پی-با-خط‌تیره>.sslip.io` ساخته می‌شود و Caddy خودش گواهی Let's Encrypt می‌گیرد. برای رفتن به دامنه‌ی واقعی، رکورد A `app.<domain>` را به آی‌پی سرور بدهید و اجرا کنید:

```bash
sudo bash /opt/iplast/infra/enable-web.sh isfahanplast.co
```

### ۴. نصب روی سرور داخل ایران (نصب فعلی)

نصب فعلی روی سرور mobinhost با آی‌پی `87.107.129.163` و آدرس `https://iplast.keyfitapp.ir` است (دامنه‌ی `iplas.co` کنار گذاشته شد؛ مثال‌های زیر با همان نام قدیمی نوشته شده‌اند). این سرور مشکل‌هایی دارد که سرور خارج ندارد:

| مشکل | راه‌حل |
|---|---|
| تلگرام، OpenAI، گیت‌هاب و npm مستقیم در دسترس نیستند | xray روی خود سرور (`infra/proxy`) |
| پورت‌های ۸۰ و ۴۴۳ دست Caddy پروژه‌ی دیگری (niva) است | `web` روی `172.17.0.1:8088` با HTTP؛ Caddy مشترک HTTPS را می‌دهد |
| Let's Encrypt از خارج به سرور نمی‌رسد | گواهی از راه DNS کلادفلر (`infra/tls/cert-cloudflare.sh`) |

> روی این سرور پروژه‌ی keyfit هم هست؛ به آن دست نزنید. niva و karnik در ۲۰۲۶-۱۱-۰۹ به درخواست کارفرما حذف شدند و پورت‌های ۸۰/۴۴۳ حالا دست کانتینر `iplast-front` است (`infra/front/install.sh`، کانفیگ `/opt/iplast-front/Caddyfile`). جاهایی از این بخش که از Caddy نیوا نام می‌برند، تاریخچه‌ی نصب اول هستند.

#### ۴.۱ پراکسی (xray)
1. باینری xray را در `/opt/iplast-proxy/xray` بگذارید (از [Xray-core releases](https://github.com/XTLS/Xray-core/releases)، با یک کانفیگ اولیه که از اشتراک ساخته شده؛ تا پراکسی بالا نیامده دانلود مستقیم از گیت‌هاب ممکن است کار نکند و باید فایل را دستی منتقل کنید).
2. ابزارهای میزبان را نصب کنید: `sudo bash /opt/iplast/infra/proxy/install.sh`.
   این دستور سرویس `iplast-proxy` (xray روی `127.0.0.1:10809`)، `iplast-proxy-apply.path` و بررسی هر ۵ دقیقه (`iplast-proxy-check.timer`) را نصب می‌کند و `git config http.proxy` را تنظیم می‌کند.
3. همان کانفیگ داخل Docker هم به‌صورت سرویس `proxy` (پروفایل `proxy`) روی `proxy:10809` اجرا می‌شود، چون فایروال میزبان اجازه نمی‌دهد کانتینرها به پورت‌های میزبان وصل شوند. کانتینر پراکسی `/etc/ssl/certs` میزبان را mount می‌کند، چون ایمیج slim گواهی‌های CA ندارد و بدون آن xray خطای `x509: certificate signed by unknown authority` می‌دهد.
4. **عوض کردن اشتراک:** در پنل مدیریت، بخش «پراکسی سرور» (فقط مدیر ارشد)، لینک جدید را بگذارید. هر سرور اول با `api.telegram.org` آزمایش می‌شود و بعد فعال می‌شود. اگر سرور فعال قطع شود، هر ۵ دقیقه یکی دیگر از همان اشتراک جایگزین می‌شود.

#### ۴.۲ نصب برنامه
```bash
sudo OUTBOUND_PROXY=http://127.0.0.1:10809 SHARED_WEB=172.17.0.1:8088 bash /opt/iplast/infra/setup.sh
```

متغیرهایی که این حالت به `.env` اضافه می‌کند:
```
BUILD_PROXY=http://127.0.0.1:10809      # git و ساخت ایمیج روی میزبان
COMPOSE_PROFILES=proxy
HTTPS_PROXY=http://proxy:10809          # api و bot داخل Docker
HTTP_PROXY=http://proxy:10809
NO_PROXY=localhost,127.0.0.1,api,postgres,redis,web,migrate,bot
NODE_USE_ENV_PROXY=1                    # fetch سراسری Node 22 از پراکسی رد شود (API)
PROXY_INBOX=/opt/iplast-proxy/inbox     # وضعیت پراکسی و اشتراک جدید از پنل
SITE_ADDR=:80
HTTP_BIND=172.17.0.1:8088
HTTPS_BIND=127.0.0.1:18443
```

**نکته‌ی ربات:** grammY از node-fetch استفاده می‌کند و `NODE_USE_ENV_PROXY` روی آن اثری ندارد. Agent با گزینه‌ی `proxyEnv` در Node 22 هم نادیده گرفته می‌شود. به همین دلیل `apps/bot/src/main.ts` یک `TunnelAgent` دارد که برای هر درخواست تلگرام از `HTTPS_PROXY` تونل `CONNECT` باز می‌کند.

#### ۴.۳ دامنه و HTTPS با Cloudflare
1. دامنه (`iplas.co`) را به Cloudflare اضافه کنید و Nameserverها را نزد ثبت‌کننده‌ی دامنه به این دو عوض کنید: `aarav.ns.cloudflare.com` و `kenia.ns.cloudflare.com`. صبر کنید تا وضعیت دامنه در Cloudflare **Active** شود.
2. رکورد `A` برای `iplast` با مقدار `87.107.129.163` بسازید و آن را روی **DNS only** (ابر خاکستری) بگذارید. پراکسی Cloudflare به سرور داخل ایران نمی‌رسد.
3. در Cloudflare یک API Token با الگوی «Edit zone DNS» و محدود به همین zone بسازید.
4. روی سرور اجرا کنید:
   ```bash
   sudo bash /opt/iplast/infra/tls/cert-cloudflare.sh iplast.iplas.co
   ```
   بار اول توکن را بدون نمایش می‌پرسد و در `/opt/iplast-tls/cf-token` (`chmod 600`) ذخیره می‌کند. بعد این کارها را انجام می‌دهد:
   - lego را از راه پراکسی دانلود می‌کند و گواهی Let's Encrypt را با چالش DNS-01 می‌گیرد.
   - گواهی را در volume داده‌ی Caddy مشترک (`/data/iplast/`) کپی می‌کند.
   - بلوک `iplast.iplas.co` را در `/opt/niva/deploy/panel-ip.Caddyfile` جایگزین می‌کند و Caddy را از راه stdin بارگذاری مجدد می‌کند.
   - `SITE_HOST` و `MINIAPP_URL` را در `.env` عوض می‌کند و سرویس‌ها را بالا می‌آورد. ربات دکمه‌ی منو را خودش روی آدرس جدید می‌گذارد.
   - تمدید هفتگی را با `iplast-tls.timer` نصب می‌کند.
5. خطای `failed to find zone` یعنی دامنه هنوز در Cloudflare فعال نشده است.

### ۵. به‌روزرسانی (Deploy)

نیازی به SSH ورودی نیست. `iplast-autodeploy.timer` هر ۲ دقیقه `origin/main` را بررسی می‌کند. اگر commit جدیدی باشد، این کارها را می‌کند:
- `git reset --hard origin/main`
- ابزارهای میزبان (پراکسی، خود autodeploy و پشتیبان‌گیری) را به‌روز می‌کند.
- `docker compose up -d --build --remove-orphans` را اجرا می‌کند. این کار ۳ تا ۵ دقیقه طول می‌کشد.

نتیجه، موفق یا ناموفق، با ربات برای اولین مدیر فرستاده می‌شود و لاگ در `/var/log/iplast-deploy.log` است. برای deploy دستی:

```bash
sudo FORCE=1 /usr/local/bin/iplast-autodeploy
```

### ۶. پشتیبان‌گیری

`infra/backup.sh` هر جمعه ساعت ۰۳:۳۰ اجرا می‌شود (`iplast-backup.timer`). اولین بار هم ۱۰ دقیقه بعد از نصب اجرا می‌شود. خروجی در `/opt/iplast-backups/<تاریخ_ساعت>/` است و فقط root به آن دسترسی دارد. ۸ نسخه‌ی آخر (دو ماه) نگه داشته می‌شود (`BACKUP_KEEP` در `.env`).

| فایل | محتوا |
|---|---|
| `db.sql.gz` | dump کامل PostgreSQL |
| `uploads.tar.gz` | همه‌ی فایل‌های بارگذاری‌شده: عکس محصول، اسناد مالی، PDF لیست قیمت |
| `settings.tar.gz` | `.env`، اشتراک و کانفیگ پراکسی، توکن Cloudflare و حساب Let's Encrypt (**شامل رمزها؛ فقط روی سرور**) |
| `commit.txt`، `SHA256SUMS`، `backup.log` | نسخه‌ی کد، چک‌سام‌ها و گزارش |

یک فایل کامل (دیتابیس + همه‌ی فایل‌ها) با ربات برای مدیر ارشد هم فرستاده می‌شود تا یک نسخه بیرون از سرور بماند؛ اگر بزرگ‌تر از ۴۵ مگابایت باشد چند بخش می‌شود و با `cat iplast-backup-*.part* > backup.tar` دوباره یکی می‌شود. این تنها پیام پشتیبان‌گیری است (بی‌صدا). برای خاموش کردن این ارسال، `BACKUP_TELEGRAM=0` را در `.env` بگذارید. `settings.tar.gz` هرگز ارسال نمی‌شود.

دستورها:
```bash
sudo bash /opt/iplast/infra/backup.sh             # همین حالا
ls -l /opt/iplast-backups/                         # فهرست نسخه‌ها
systemctl list-timers iplast-backup.timer          # زمان اجرای بعدی
```

برای امنیت بیشتر، گاهی پوشه‌ی `/opt/iplast-backups` را به جای دیگری هم کپی کنید.

#### بازگردانی پشتیبان
```bash
cd /opt/iplast
B=/opt/iplast-backups/<تاریخ_ساعت>
# تنظیمات (روی سرور نو، قبل از setup.sh):
sudo tar -xzf $B/settings.tar.gz -C /
# پایگاه داده:
docker compose stop api bot
gunzip -c $B/db.sql.gz | docker compose exec -T postgres sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB"'
# عکس‌ها:
docker compose exec -T api sh -c 'tar -xzf - -C /data/uploads' < $B/uploads.tar.gz
docker compose up -d
```

روی سرور نو، تنظیمات را پیش از `setup.sh` بازگردانید. در این حالت `setup.sh` همان `.env` قبلی را نگه می‌دارد. بعد `touch /opt/iplast/.seeded` را اجرا کنید تا کاتالوگ دوباره روی داده‌ها بارگذاری نشود، و سپس پایگاه داده و عکس‌ها را بازگردانید.

### ۶.۵ ایجنت فروش هوش مصنوعی

هر پیام مشتری، چه در ربات و چه در گفتگوی مینی‌اپ، اول به ایجنت می‌رسد (`apps/api/src/assistant/sales-agent.service.ts`). ایجنت سفارش را از کاتالوگ و لیست قیمت کامل می‌کند و بعد از «ثبت کن» مشتری، پیش‌فاکتور را با کانال `agent` ثبت می‌کند. کارشناس فروش فقط آن را تأیید یا اصلاح می‌کند و مدیر ارشد تأیید نهایی می‌دهد.

ایجنت در این موارد گفتگو را به کارشناس می‌سپارد و کارشناس در تلگرام خبردار می‌شود:
- مشتری کارشناس بخواهد.
- عکس یا فایل بفرستد.
- تخفیف یا شکایت داشته باشد.
- ایجنت پاسخ را نداند.

از آن به بعد پیام‌های همان گفتگو برای کارشناس فرستاده می‌شود. در پنل، بخش «گفتگوها»، با «برگرداندن به ایجنت» گفتگو دوباره دست ایجنت می‌افتد.

تنظیمات `.env`:
- `OPENAI_API_KEY` لازم است.
- با `SALES_AGENT=0` ایجنت خاموش می‌شود و پیام‌ها مثل قبل مستقیم به کارشناس می‌روند.

وضعیت اتصال و آمار ایجنت در پنل، بخش «تنظیمات ← ایجنت هوش مصنوعی» است.

### ۶.۶ روند فروش: پیش‌فاکتور، ارسال، چک و اسناد

- **پیش‌فاکتور:** مشتری یا ایجنت سفارش ثبت می‌کند. کارشناس فروش در پنل (سفارش‌ها ← منتظر کارشناس) قیمت اقلام استعلامی را می‌گذارد و در صورت نیاز تعداد، تخفیف و کرایه را عوض می‌کند. اگر چیزی تغییر کند، پیش‌فاکتور نهایی برای مشتری (ربات و مینی‌اپ) می‌رود و مشتری تأیید می‌کند. بعد مدیر تأیید نهایی می‌دهد و فاکتور خودکار صادر می‌شود.
- **مهلت پیش‌فاکتور:** ۴۸ ساعت. با `PROFORMA_TTL_HOURS` در `.env` یا Setting `proforma.ttlHours` قابل تغییر است. پیش‌فاکتور منقضی را کارشناس دوباره می‌فرستد.
- **شرایط فروش مشتری (نقدی / مدت‌دار):** هر مشتری دو درصد دارد: «نقدی» (مثلاً ۴۰٪ زیر قیمت لیست) و «مدت‌دار» (مثلاً ۳۰٪ زیر قیمت لیست با چک ۳ ماهه). برای هر دسته‌ی کالا می‌شود درصد جدا گذاشت. در پنل: مشتریان ← مشتری ← شرایط فروش. مشتری در مینی‌اپ قیمت هر دو را می‌بیند و موقع ثبت سفارش یکی را انتخاب می‌کند؛ کارشناس در پیش‌فاکتور می‌تواند نوع فروش را عوض کند و قیمت‌ها با درصد دیگر دوباره حساب می‌شود. قیمت اختصاصی یک کالا بر درصدها مقدم است.
- **جذب مشتری (پنل ← جذب مشتری):** هر کارشناس لینک دعوت و QR کد خودش را دارد (`t.me/<ربات>?start=ref_<کد>`)؛ کسی که با آن بیاید، با اولین سفارش مشتریِ همان کارشناس می‌شود. «تخفیف سفارش از اپ» (تنظیم `sale.appBonusPct`) روی سفارش‌هایی که مشتری خودش در مینی‌اپ ثبت کند، به‌عنوان تخفیف ویژه می‌نشیند. «خبر تغییر قیمت» برای همه‌ی مشتری‌ها پیام می‌فرستد. ویدیوی آموزشی: مدیر ویدیو را با کپشن `#آموزش` برای ربات بفرستد؛ بعد از /start برای مشتری‌ها می‌رود.
- **ثبت سفارش تلفنی (سفارش‌ها ← ثبت سفارش تلفنی):** کارشناس برای مشتری سفارش ثبت می‌کند (کانال `admin`)؛ پیام‌های وضعیت و پیش‌فاکتور به کاربران خود مشتری می‌رود، نه کارشناس.
- **سقف اعتبار:** در پرونده‌ی مشتری ← مشخصات (فقط مدیر). اگر بدهی با سفارش جدید از سقف بگذرد، در پیام تأیید نهایی ربات و در پنل هشدار می‌آید و در پیشخوان فهرست می‌شود.
- **لینک پیش‌فاکتور برای حسابدار:** `POST /api/orders/:id/share` لینک فقط‌خواندنیِ ۱۴ روزه می‌دهد (`?doc=`)، که بدون ورود در مرورگر باز و چاپ/PDF می‌شود.
- **گزارش هفتگی:** شنبه‌ها بین ۹ تا ۱۳ (تهران) خلاصه‌ی فروش، سفارش، طلب، چک‌ها و فروش کارشناس‌ها برای مدیران در ربات می‌آید.

- **ارسال بار:** انبار باربری، شماره بارنامه، راننده، پلاک، کرایه و عکس یا PDF بارنامه را ثبت می‌کند. همه برای مشتری فرستاده می‌شود. یک سفارش می‌تواند چند بار داشته باشد.
- **چک‌ها:** ۳ روز قبل و روز سررسید به مشتری و کارشناس یادآوری می‌شود (فقط ۸ تا ۲۱). مدیر روزی یک فهرست می‌گیرد. چک برگشتی به مشتری، کارشناس و مدیر خبر داده می‌شود.
- **اسناد مالی:** عکس یا PDF (حداکثر ۱۰ مگابایت) در پرونده‌ی مشتری، در `UPLOAD_DIR/docs`. این پوشه در پشتیبان هفتگی هست.
- **آزمون:** `apps/api/test/e2e.mjs` و `apps/api/test/ticks.cjs`.

### ۷. مدیر ارشد و کارکنان

- آیدی‌های `ADMIN_TELEGRAM_IDS` در `.env` فقط بار اول مدیر ارشد ساخته می‌شوند. بعد از آن نقش‌ها فقط از پایگاه داده خوانده می‌شوند.
- **انتقال مدیر ارشد:** در پنل، بخش «کارکنان»، آیدی نفر جدید را با نقش «مدیر ارشد» اضافه کنید. بعد مدیر جدید حساب قبلی را غیرفعال می‌کند.
- اگر هیچ مدیر ارشد فعالی نماند، با راه‌اندازی دوباره، آیدی داخل `.env` دوباره مدیر ارشد می‌شود.
- پنل مدیریت با کارت «پنل مدیریت» در مینی‌اپ یا دستور `/admin` در ربات باز می‌شود.

### ۹. عیب‌یابی

| نشانه | بررسی |
|---|---|
| ربات جواب نمی‌دهد | `docker compose logs --tail 50 bot`. خطای `ECONNRESET` یعنی پراکسی کار نمی‌کند: `docker compose logs proxy`، `systemctl status iplast-proxy` و وضعیت در پنل ← «پراکسی سرور» |
| `x509: unknown authority` در لاگ proxy | mount `/etc/ssl/certs` در `docker-compose.yml` |
| deploy انجام نمی‌شود | `journalctl -u iplast-autodeploy -n 50` و `/var/log/iplast-deploy.log`. `git fetch` به پراکسی میزبان نیاز دارد |
| سایت باز نمی‌شود | `curl -sI http://172.17.0.1:8088` (کانتینر web)، بعد پروکسی جلو: `docker logs --tail 50 iplast-front` |
| تغییر تنظیمات پروکسی جلو | `/opt/iplast-front/Caddyfile` را ویرایش و بارگذاری کنید: `docker exec iplast-front caddy reload --config /etc/caddy/Caddyfile --adapter caddyfile` (این پروکسی با `infra/front/install.sh` جای Caddy قدیمی نیوا را گرفت و keyfitapp.ir را هم سرو می‌کند) |
| گواهی تمدید نشد | `journalctl -u iplast-tls -n 50`. توکن Cloudflare باید معتبر باشد |
| پشتیبان‌گیری | `/opt/iplast-backups/<آخرین>/backup.log` و `journalctl -u iplast-backup -n 30` |
| از خارج ایران باز نمی‌شود | طبیعی است: سرور فقط از داخل ایران در دسترس است. کاربر با VPN ممکن است نتواند وصل شود |

**تایپ در کنسول VNC مرورگر:** نویسه‌های shift‌دار (`:`، `_`، `|`، `>`، `&`) گاهی اشتباه تایپ می‌شوند. دستورها را کوتاه وارد کنید و قبل از Enter بررسی کنید، یا دستور را از یک فایل اسکریپت اجرا کنید.

### ۱۰. امنیت

- توکن ربات، رمز پایگاه داده، `JWT_SECRET`، `INTERNAL_KEY` و کلیدهای OpenAI، کاوه‌نگار و Cloudflare فقط در `.env` و `/opt/iplast-tls` روی سرور هستند (`chmod 600`).
- اگر توکنی جایی دیده یا فرستاده شده، آن را عوض کنید:
  - ربات: در @BotFather دستور `/revoke` را بزنید، توکن جدید را در `BOT_TOKEN` بگذارید و `docker compose up -d` را اجرا کنید.
  - Cloudflare: توکن قبلی را در داشبورد Cloudflare حذف کنید و فایل `/opt/iplast-tls/cf-token` را با توکن جدید بازنویسی کنید.
- نسخه‌ی پشتیبان `settings.tar.gz` شامل همه‌ی این رمزهاست. آن را جایی نفرستید.
